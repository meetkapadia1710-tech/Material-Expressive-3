          - heading "Why are tokens important?" [level=2]
        - region:
          - button "copy link to this section": link
          - text: Copy link
          - paragraph: Tokens make it possible for a design system to have a single source of truth – a repository where style choices are recorded and changes can be tracked. Because tokens are reusable and purpose-driven, they can define system-wide updates to themes and contexts. For example, you can use tokens to systematically apply a high-contrast color palette for improved visibility, or change the typographic scale to ensure that text is legible on a TV screen. By using tokens for design and implementation, style updates propagate consistently through an entire product or suite of products. They also help designers and engineers "speak the same language,” reducing confusion during handoff from design to implementation.

        - region:
          - button "copy link to this section": link

          - paragraph: "There are three classes of tokens in Material:"
          - list:
            - listitem: Reference tokens All available tokens with associated values.
            - listitem: System tokens Decisions and roles that give the design system its character, from color and typography, to elevation and shape.
            - listitem: Component tokens The design properties assigned to elements in a component, such as the color of a button icon.
          - paragraph: With three classes of tokens, teams can update design decisions globally or apply a change to a single component.

          - heading "Reference tokens" [level=3]
          - paragraph: These tokens make up all of the style options available in a design system.
          - paragraph: They usually point to a static value – such as a color hex code or font size – but can also point to other reference tokens. Reference tokens don't change based on context.
          - paragraph: By providing a list of options, reference tokens give your team a starting point of approved colors, typography, measurements, etc.
          - paragraph:
            - text: All reference tokens start with the prefix
            - strong: ref
            - text: .

          - heading "System tokens" [level=3]
          - paragraph: These are the decisions that systematize the design language for a specific theme or context.
          - paragraph: System tokens define the purpose a reference token serves in the UI.
          - paragraph: This is where theming occurs. The system token can point to different reference tokens depending on the context, such as a light or dark theme.
          - paragraph: Whenever possible, system tokens should point to reference tokens rather than static values.
          - paragraph:
            - text: All system tokens start with the prefix
            - strong: sys
            - text: .

          - heading "Component tokens (in development)" [level=3]
          - paragraph: These represent the elements required to compose a component, such as containers, label text, icons, states, and their values such as size, shape, color, or elevation.
          - paragraph: Whenever possible, component tokens should point to a system or reference token, and not contain hardcoded values such as hex codes.
          - paragraph: Not every stylistic choice of a component will be able to be expressed as a token, but whenever a design choice applies to multiple components of similar intent, a token should be used.
